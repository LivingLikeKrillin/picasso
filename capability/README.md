# `capability` — 투영과 판정

프로파일 → `Capability`(§7.2 의 투영), 그리고 요구 집합 대 `Capability`(§5.4 의 협상 판정).

## 왜 따로 있나

★**미믹과 어댑터 호스트가 같은 함수를 써야 한다.** 판정이 두 벌이면 **같은 설정 파일을 들고 미믹에서는
통과하고 실물에서는 거절당하는 일**이 가능해진다 — 소비자가 엔드포인트만 바꿔 오간다는 주장이 거기서 죽는다.

`harness/HostParityTest` 가 그 하나임을 밖에서 확인한다. ★다만 **동치 시험은 공유 판정 자체의 결함은 못 잡는다**
(둘이 같이 틀린다).

## 경계

**전송을 모른다.** gRPC 의존이 없다 — 판정은 값의 문제이고, 그 값을 어떻게 나르는지는 계약의 일이다.
그리고 기종을 모른다(게이트 7번의 대상).

## 무엇이 여기 있나

`CapabilityProjection`(투영 표가 곧 명세다 — 능력을 하드코딩하면 완료 기준 10 에서 걸린다) ·
`Negotiator`(`Negotiation.Judged` / `Unparseable` — **읽지 못한 요구는 거절이 아니라 판정 불가**다).
