# capability — 능력 투영 및 협상 판정 엔진 (Capability Projection & Negotiation)

기종 프로파일 JSON 메타데이터를 계약 규격인 `Capability` 모델로 변환하는 투영(Projection, §7.2)과, 상류 작업 요구 사양과 기체 가용 능력 간의 런타임 협상 적합성을 평가하는 판정(Negotiation, §5.4)을 수행하는 모듈입니다.

---

## 1. 아키텍처 설계 원칙: 단일 판정 엔진 공유 (Single Decision Logic)

에뮬레이터(`mimic`)와 실물 어댑터 호스트(`adapter-host`)가 동일한 판정 함수를 공유합니다. 판정 알고리즘이 모듈별로 이원화될 경우 동일한 요구 사양 설정에 대해 에뮬레이터에서는 승인되고 실물 기체에서는 거절되는 불일치가 발생할 수 있기 때문입니다.

통합 테스트 하네스의 `harness/HostParityTest`가 두 실행 경로가 완전히 동일한 판정 결과를 도출하는지 지속적으로 동치성을 검증합니다.

---

## 2. 아키텍처 경계 및 관심사 분리

- **네트워크 전송 프로토콜 독립성**: 전송 계층(gRPC)을 인지하지 않으며 관련 의존성을 배제합니다 (소스 코드 내 `io.grpc` 0건). 능력 판정은 순수한 도메인 값 기반 연산이며, 직렬화 및 원격 전송은 계약 계층의 책임입니다.
- **기종 비인지 준수**: 기종 중립 모듈로서 게이트 검사 7번(기종 분기 금지)을 엄격히 준수합니다.

---

## 3. 핵심 구성 요소

- `CapabilityProjection`: 프로파일 속성 매핑을 통해 계약 규격의 `Capability` 인스턴스를 생성하는 정적 투영 엔진.
- `Negotiator`: 클라이언트가 제시한 요구 파라미터와 기체 가용 능력 간의 호환성 평가 (`Negotiation.Judged` 정상 판정 및 `Unparseable` 미지원 구문 처리 — 해석 불가능한 요구는 단순 거절이 아닌 판정 불가로 명확히 분리).
