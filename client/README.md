# client — 인터페이스 계약 씬 클라이언트 SDK (Thin Client SDK)

표준 인터페이스 계약(제4계층)을 호출하여 이종 로봇의 기능을 실행하고 검증하기 위한 경량 클라이언트 라이브러리입니다. `harness` 모듈이 에뮬레이터 및 실물 어댑터 호스트를 구동할 때 사용하며, `picasso` 미들웨어의 `ClientRobotPort`가 내부적으로 본 클라이언트를 래핑하여 호출합니다.

---

## 1. 아키텍처 설계 원칙: 완전한 기종 비인지 (Vendor-Agnostic)

- **기종별 코드 분기 일체 배제**: 게이트 검사 7번을 통해 소스 코드 내에 특정 벤더나 모델 명칭이 유입되는 것을 엄격히 차단합니다. *"서로 다른 기능을 가진 이종 로봇을 동일한 클라이언트 코드로 제어한다"*는 완료 기준 1번을 충족합니다.
- **요구 사양의 선언적 설정 파일화**: 작업 수행에 필요한 요구 사양 집합은 코드가 아닌 **선언적 JSON 설정 파일**(`profile/requirements/`, §5.4)로 관리하여, 코드 내에 특정 기종에 대한 지식이 은닉되는 것을 방지합니다.

---

## 2. 주요 구성 요소

- `PicassoClient`: 계약 gRPC 호출을 위한 씬 래퍼. 기체 가용 능력 메타데이터는 `capability_epoch` 단위로 로컬 캐싱하여 불필요한 RPC를 최소화합니다.
- `TaskFollower` / `EventConsumer`: `WatchTask` gRPC 스트림 및 MQTT 비동기 발행 이벤트를 안정적으로 수신하기 위한 클라이언트 수신 버퍼, 타임스탬프 기반 재정렬 창 및 멱등성 보장 로직.
- `cli/Main.kt`: CLI 실행 진입점 (`client --target <URI> --robot <ID> --requirements <FILE>`).

---

## 3. 모듈 경계 및 격리 검증

요구 사양 파일을 읽기 위해 `ProfileDocument` 타입이 클래스패스에 포함되나, 클라이언트 코드가 프로파일의 내부 세부 구조에 결합되지 않도록 `ClientBoundaryTest`를 통해 아키텍처 경계를 엄격히 검증합니다.
