# gate — 거버넌스 및 계약 정합성 자동화 검증 라이브러리

인터페이스 계약(`contracts`)과 기종 프로파일 간의 불일치 및 아키텍처 규칙 위반을 방지하는 정적 검증 모듈입니다. CI 파이프라인과 `registry` 서비스 런타임이 동일한 검증 로직 라이브러리를 공유하여 호출함으로써(ADR 22), CI 통과 기준과 런타임 수용 기준 간의 드리프트 발생을 원천 차단합니다.

---

## 1. 게이트 8대 핵심 정합성 검사 (Checks 1~8)

| 검사 번호 | 검증 대상 및 위반 차단 사유 |
|---|---|
| **1 · 2** | `buf lint` 및 `buf breaking` — Protobuf 스타일 규약 준수 및 하위 호환성 파괴 변경 차단 |
| **3** | 기종 프로파일 JSON Schema 및 4대 구조적 정합성 규칙 검증 (스키마 표현 한계 보완) |
| **4** | 계약 ↔ 프로파일 간 교차 참조 — Proto에 정의되지 않은 스킬이나 파라미터 키를 프로파일이 선언 시 차단 |
| **5** | `contracts` 모듈의 프로젝트 내부 의존성 0 검증 (계약의 순수성 보장) |
| **6** | 프로파일 개정 시 파괴적 변경 검증 (Major 버전 상향 없는 기능 축소 및 필수 키 제거 차단) |
| **7** | **기종 분기 금지 (Model Branching)** — 기종 중립 모듈(`picasso`, `client` 등) 내 벤더/모델 명칭 하드코딩 차단 |
| **8** | **코드 수정 없는 신규 기종 추가** — 기종 프로파일 추가 PR에 소스 코드 수정이 포함될 경우 차단 |

7번과 8번 검사는 본 프로젝트의 양대 핵심 아키텍처 주장인 *"단일 클라이언트 코드로 이종 기체 제어"*와 *"코드 수정 없는 선언적 프로파일 기반 기종 확장"*을 CI 실패 조건으로 엄격히 강제합니다.

## 2. 결함 주입 기반 음성 하네스 (Negative Harness)

검사 규칙 자체가 정상 동작하는지 검증하기 위한 회귀 테스트 프레임워크입니다. `gate/negative/` 디렉터리에 사전 정의된 결함 케이스별로 저장소 트리를 임시 복제하고 결함 오버레이를 적용하여 게이트를 구동합니다. 해당 케이스에서 **지정된 특정 검사가 반드시 실패**해야만 테스트가 통과됩니다.

이는 과거 게이트 검사가 자원 누락 시 아무런 검사도 수행하지 않고 종료 코드 0(정상)을 반환했던 결함을 방지하기 위해 도입되었으며, `--require` 플래그를 통해 필수 입력 자원을 강제하고 무검증 통과(Silent Pass)를 원천 차단합니다.

---

## 3. 문자열 기반 검사 도입 배경 (ADR 23)

5번(의존성) 및 7번(기종 분기) 검사는 복잡한 컴파일러 AST 파서 대신 문자열 정규식 기반으로 구현되어 있습니다. 이는 악의적 우회 차단이 아닌 일상적인 엔지니어링 실수를 방지하는 것이 주 목적이며, AST 도입에 따른 유지보수 비용을 절감하기 위함입니다. 런타임에 동적으로 기종 식별자를 합성하거나 우회하는 패턴에 대한 한계는 한계 대장(§15.6, §15.11, §15.28)에 명시되어 있습니다.

---

## 4. 모듈 경계 및 빌드 파이프라인

본 모듈은 `contracts`에 대해 컴파일타임 라이브러리 의존성을 갖지 않습니다. 게이트 검증에 필요한 것은 Protobuf 생성 코드가 아닌 바이너리 디스크립터(`FileDescriptorSet`) 바이트이며, 이를 런타임 파일 입력으로 수신합니다. `:gate:test` 태스크는 `:contracts:generateProto` 태스크에 직접 의존하여 빌드 시 항상 최신 디스크립터 바이트를 기반으로 검증을 수행합니다 (§15.111).

또한 저장소 내 텍스트 진술과 실제 코드 구현 간의 정합성을 대조하는 `DocumentClaimsTest`가 본 모듈에 배치되어 운영됩니다.
