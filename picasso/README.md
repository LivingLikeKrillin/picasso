# picasso — 지능형 미들웨어 코어 (Middleware Core Engine)

상위 제조·물류 실행 시스템(MES/WMS)과 하위 이종 로봇 및 현장 자동화 설비 간의 작업을 조율하는 **아키텍처 제3계층(배정 및 완료 결정 엔진)**의 핵심 구현 모듈입니다 (ADR 38).

상류로부터 인입된 복합 작업 지시(JobOrder)를 원자적 실행 단위(`ExecutionUnit`) 시퀀스로 분해하고, 하위 계약 계층(제4계층)을 통해 로봇에 하달하며, 로봇의 자체 완료 보고와 **현장 물리 설비(Cell/PLC)의 센서 신호**를 결합하여 최종 작업 완료 여부를 결정론적으로 승인합니다.

---

## 1. 핵심 컴포넌트 구성

| 소스 파일 | 핵심 도메인 모델 및 아키텍처 역할 |
|---|---|
| `Model.kt` | **정준 도메인 모델**: 2축 상태기계(`PhysicalState` 및 `TaskState`), 4단계 근거 등급(`E0`~`E3`), `ExecutionUnit`, ISA-95 대응 `JobOrder`/`JobResponse`, `CancelReport` |
| `LogicalCapability.kt` | 상위 논리적 능력 인터페이스 및 3대 구현체 (`PrepareSequencedRack`, `DeliverContainer`, `InspectAsset`), 능력 단위 타임아웃 구성 (유효 시간창 δ, `IN_DOUBT` 유예 기간, 진행 정체 유예) |
| `Middleware.kt` | 코어 상태 엔진: 접수 → 분해 및 조합 → 실행 디스패치 → 근거 결합 판정 → 상류 통보. 단일 틱 구동 함수 `pump()` 기반의 결정론적 전이 |
| `Ports.kt` | 하위 시스템 연동 추상화 포트: `RobotPort` (인터페이스 계약 소비자), `CellSignals` (현장 설비 센서 신호, E2), `AmrFleetPort` (이송 플릿 연동, E1) |

## 2. 아키텍처 경계 및 관심사 분리

- **기종 비인지 원칙 (Vendor-Agnostic)**: 게이트 검사 7번을 통해 본 모듈 소스 코드 내 특정 벤더나 기종 명칭의 유입을 엄격히 차단합니다. 벤더별 고유 코드를 표준 분류로 변환하는 책임은 어댑터 계층(ADR 33)에 있으며, 미들웨어 코어 내에 기종별 분기(`if robot == ...`)가 존재해서는 안 됩니다.
- **능력군 추가 시 코어 엔진 불변성**: 엔진 내부에 개별 능력별 하드코딩 분기가 없습니다. `InspectAsset` 능력군 추가 시에도 코어 엔진의 로직 수정 없이 **3대 일반 규칙**(등급 상한 거절, 결과 참조 처리, 취소 거절 노출)의 매개변수화만으로 수용되었습니다 (§15.93).
- **글로벌 배차/경로 계획의 스코프 외 분리**: 공장 전체 단위의 AMR 라우팅, 배차 최적화, 전역 자원 선점은 상위 플릿 관제 시스템의 책임이며, 본 모듈은 단일 워크셀 내 작업 분해 및 상태 보증에 집중합니다.

## 3. 제3계층 특화 아키텍처 메커니즘

- **검증 불가 상태 (`UNVERIFIED`)**: 로봇은 하드웨어 완료를 보고했으나 현장 설비 센서의 확인 신호가 도달하지 않은 경우 불확실성을 명시적 상태로 보존합니다.
- **상류 승인 상태 분리 (`upstream_ack`)**: 물리적 작업 완료와 상류 시스템으로의 통보 성공 여부를 독립적인 축으로 관리하여, 네트워크 단절에 따른 통보 재시도와 물리 명령 재시도를 엄격히 분리합니다.
- **다중 소스 근거 등급 결합 (Evidence Aggregation)**: `E0`(로봇 자체 보고), `E1`(플릿 확인), `E2`(설비 센서 신호), `E3`(작업자 수동 확인)을 결합합니다. 요구되는 신뢰 등급을 충족할 수 없는 기체 조합은 접수 단계에서 선제 거절합니다.
- **지연 이벤트 보존 및 재평가**: 구성 버전 변경 중 도착한 이전 버전의 종착 이벤트는 유실되지 않고 안전하게 보존되어 신규 버전의 기대 조건에 맞춰 재평가됩니다 (§15.1).

## 4. 자동화 테스트 및 검증 매트릭스

| 테스트 클래스 | 검증 시나리오 및 보증 사항 |
|---|---|
| `SequencingRackTest` | 시나리오 ② — 4개 슬롯 순차 적재, 런타임 버전 갱신, 중간 취소 및 설비 신호 결합 · 계획 시점 사전 조건 사슬 검사 · 적재 유실의 세 축 통보 |
| `DeliverContainerTest` | 시나리오 ① — 이송 플릿 위임(`E1`) 및 자재 인계 신호 검증 |
| `InspectAssetTest` | 시나리오 ③ — 신규 능력군 추가 시 코어 엔진 코드 무수정 검증 |
| `EvidenceWindowTest` | 센서 응답 유효 시간창 δ 초과, 재확인 루프, `UNVERIFIED` 및 `VERIFICATION_MISMATCH` 처리 |
| `InDoubtTest` · `LateEventTest` | 명령 접수 불확실 상태 해소 절차 및 버전 전환 간 지연 이벤트 처리 무결성 |
| `EventStreamTest` | 상태 스냅샷 권위, 이벤트 재생 및 장애 복구 후 엔진 재동기화 |
| `ProgressStallTest` | 작업 정체 가시화 — 정량 측정이 불가능한 기체에 대한 허위 판정 배제 (계약 0.8.0 사양) |

## 5. 알려진 한계 및 엔지니어링 고려 사항

본 모듈의 단위/통합 테스트는 외부 상류 시스템과 현장 설비를 모사한 테스트 대역(`CellMimic`, `AmrFleetMimic`)을 기반으로 동작합니다. 따라서 테스트 스위트의 성공은 설계 가정 하에서의 시스템 일관성을 증명하며, 물리 실물 환경과의 실제 연동 검증 등급은 [`docs/verification.md`](../docs/verification.md)의 10·11번 항목에 명시되어 있습니다.
