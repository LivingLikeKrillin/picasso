# `adapter-boston-dynamics-orbit` — Orbit (플릿)

**기체가 아니라 플릿에 붙는 유일한 어댑터.** 그래서 ADR 37 의 *발견* 경로가 여기서만 실증된다.

## 이 표면이 계약에 얼마나 닿나

정본은 [`profile/distance/orbit.json`](../profile/distance/orbit.json) ·
[`profile/vendors/orbit.json`](../profile/vendors/orbit.json) · [`docs/vendors/orbit.md`](../docs/vendors/orbit.md).

요점만: **스킬 넷 중 `navigate_to` 하나만 든다.** 계약의 `location` 을 **저작된 미션의 이름**으로 읽어 파견한다 —
ADR 35 를 한 겹 옮긴 것이다. 조작 프리미티브도 속도 명령도 없다.

## 이 모듈에만 있는 것

- **발견** — `GET /robots` 로 플릿이 아는 기체를 얻어 적재 문으로 올린다. 자기 인스턴스를 함께 신고한다.
- **실 HTTP 클라이언트** — 남쪽이 와이어를 지나는 유일한 어댑터다(CSRF 쿠키→헤더, `Bearer`, 응답 봉투 둘).
  ★**게시 스펙과 벤더 클라이언트가 네 자리에서 어긋나고 클라이언트를 따른다.**
- **배치 런처** — 붙고 → 발견하고 → 기체마다 어댑터를 세우고 → 포트를 열고 → `ONLINE`. 그 순서가 §10.2 다.
- **진행률** — `Run.actionCount` 와 `pendingActionCount`. 벤더가 개수 둘을 준다.

## 못 하는 것

- **취소·일시정지·갱신이 없다.** 도는 미션을 멈추는 문이 게시 스펙에도 클라이언트 경로에도 없다 —
  그래서 갱신은 계약의 `UPDATE_UNSUPPORTED` 로 답한다.
- **`GetSnapshot` 이 `UNAVAILABLE` 이다.** 플릿이 기체 결함을 안 나르므로 *못 본다* 고 답하고, 그것을 *없다* 로
  접지 않는다. **소비자는 이 기체의 스냅샷을 영영 못 받는다** — 층이 하나 는 대가다.
- **일련번호도 기종도 안 준다**(기체 자원에). 그래서 발견된 기체는 일련번호가 널이고, 프로파일을 하나만 적용한다.

## 정직하게 적어 둘 것

와이어는 지나지만 **답하는 쪽은 우리가 세운 스텁**이다. CLI 와 주기 발견이 없고, **진짜 Orbit 인스턴스에
붙여 본 적이 없다**(C-3).
