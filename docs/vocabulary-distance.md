# 어휘 거리 재기 — 벤더 API 를 계약 스킬에 앉히는 절차

새 기종을 붙일 때 **가장 피곤하고 가장 위험한 단계**다. 여기서 잘못 판단하면 그 아래 기계 검증이
전부 무의미해진다 — 판정이 프로파일을 만들고, 프로파일이 협상을 만들고, 협상이 초록을 만들기 때문이다.
**기계가 보는 것은 일관성이지 정확성이 아니다.**

그래서 이 문서는 맛을 보장하지 않는다. 하는 일은 하나다 — **순서를 정해서 실수할 자리를 줄인다.**

산출물은 `profile/distance/<기종>.json` 한 장이고 형식은 [`profile/schema/distance.schema.json`](../profile/schema/distance.schema.json)
이 정한다. 그것을 지키는 것은 `gate` · `VocabularyDistanceTest` 의 시험 열셋이다.

---

## 1. 순서 아홉

**번호대로 한다.** 특히 3 번이 4 번보다 먼저인 것이 요점이다.

| | 하는 일 | 남는 곳 |
|---|---|---|
| 1 | **조사 범위를 먼저 정하고 적는다.** 무엇을 전수로 볼지 — 서비스 목록 · 메시지 정의 · 클라이언트 코드 · 벤더 예제 | `survey_scope` |
| 2 | **벤더 원문에서 이름을 뽑는다.** `tools/vendor-manifest/`. 원문은 저장소에 안 들인다 — 이름과 sha256 만 | `adapter-*/src/test/resources/vendor-manifest.txt` |
| 3 | **계층을 정한다.** 우리 태스크 생명주기(수락 · 일시정지 · 취소 · 재시도 · 사람 개입)와 모양이 같은 벤더 층이 있는가 | `layer.vendor_layer` |
| 4 | **계약 파라미터를 하나씩 꺼내 벤더의 어느 자리에 앉는지 적는다.** 못 찾으면 `NOT_SURVEYED` 로 두고 넘어간다 | `parameter_map` |
| 5 | **표를 보고 판정한다.** 표가 먼저고 판정이 나중이다 | `reachable` · `missing` |
| 6 | **제약에 유형을 붙인다.** `YES` 인 칸에도 붙는다 | `limitations` |
| 7 | **어댑터가 떠안을 것을 적는다.** 이것이 곧 코드 견적이다 | `adapter_must_own` |
| 8 | **검토 도장을 찍는다** | `review` |
| 9 | 그 **뒤에** 프로파일을 쓴다 | `profile/profiles/<기종>.json` |

**9 번이 어댑터와도 묶인다.** 프로파일이 선언한 스킬을 그 기종 어댑터가 실제로 드는지 시험이 본다 — 미믹은 프로파일이 곧 거동이라 프로파일과 절대 안 어긋나므로, **미믹이 도는 것은 어댑터에 대한 증거가 아니다.**

**3 번이 왜 먼저인가.** 계층 한 칸이 그 기종 판정 전부를 결정하기 때문이다. G1 은 `NONE` 이고
(`sport` 서비스가 명령만 준다) Spot 은 `MISSION` 이다. **기종 사이의 거리는 스킬마다 다른 것이 아니라
계층이 어긋난 것**이며, 계층을 안 정하고 스킬부터 보면 같은 결론에 스킬 수만큼 돌아가게 된다.

**5 번이 왜 4 번 뒤인가.** 판정부터 내리면 표가 판정을 정당화하는 서류가 된다. 표를 먼저 채우면
**빈칸이 판정을 막는다** — 필수 파라미터에 `NOT_SURVEYED` 가 하나라도 있으면 `YES` 를 못 쓴다(기계가 막는다).

## 2. 함정 여섯 — 전부 이 저장소가 실제로 물린 것이다

| 함정 | 물린 자리 | 막는 법 |
|---|---|---|
| **범위를 안 세고 판정한다** | Spot 을 서비스 **54 개 중 3 개**만 읽고 재 놓고 *"이 벤더에 무엇이 없다"* 를 적었다. 전수 조사에서 결론 셋이 뒤집혔다 | 순서 1 번. `survey_scope` 가 필수다 |
| **없는 것과 못 하는 것을 안 가른다** | *"고수준 놓기 액션이 없다"* → *"놓기를 못 한다"*. `pick_place` 를 하루에 두 번 고쳤다 | **있는 것을 조합하는 것과 없는 것을 짓는 것은 다르다.** 앞은 `SYNTHESIZED`, 뒤는 `UNMAPPED` |
| **메서드가 없으면 정보도 없다고 읽는다** | G1 에 취소 메서드는 없는데 토픽 `SportModeState_` 에 `task_id` · `task_time` 이 있었다 | 순서 2 번을 **메시지 정의까지** 돌린다. 매니페스트가 토픽도 뽑는다 |
| **판정의 범위를 안 적는다** | *"진행 중 동작을 취소하는 메서드가 없다"* 가 **로코 표면에만** 참이었다 | 판정 문장에 어느 표면의 이야기인지를 함께 쓴다 |
| **낱말이 같으면 뜻도 같다고 읽는다** | `DELIVERED` 는 *도착 ∧ 하역 ∧ 인수 ∧ 미보유* 다. 벤더의 "도착" 을 그냥 이으면 **거짓 완료**가 난다 | 계약 쪽 낱말의 **성립 조건을 펼쳐 적고** 벤더 쪽과 하나씩 댄다 |
| **기종 단위로 판정한다** | Spot 은 명령 계층만 있어도 `move_relative` 는 돈다. 죽는 것은 `navigate_to` 뿐이다 | **표면 단위로 본다.** `reachable` 도 `limitations` 도 칸마다 따로다 |

★**이 목록이 짧은 것은 함정이 여섯뿐이어서가 아니라 여섯 번 물렸기 때문이다.** 일곱 번째를 물면 여기 적는다.

## 3. 대응의 다섯 가지 — `parameter_map[].kind`

| 값 | 뜻 | 예 |
|---|---|---|
| `DIRECT` | 벤더 인자 하나에 그대로 간다 | Digit `location` → `action-goto.reference-frame` |
| `CONVERTED` | 뜻은 같은데 단위 · 기준계 · 표현이 달라 어댑터가 옮긴다 | Spot `duration` → `end_time`(상대 초 → 절대 시각) |
| `SYNTHESIZED` | 벤더에 그 자리가 없어 어댑터가 여럿을 조합해 만든다 | Spot `destination` — 팔 궤적과 그리퍼의 순서 |
| `UNMAPPED` | **대응이 없다는 판정.** 1 차 근거가 있어야 쓴다 | |
| `NOT_SURVEYED` | **판정을 안 했다.** 아직 안 본 칸 | 선택 파라미터 넷 |

★**`UNMAPPED` 와 `NOT_SURVEYED` 를 가르는 것이 이 표의 요점이다.** 앞은 주장이고 뒤는 빚이다.
*부재를 단정하려면 1 차 근거가 있어야 한다* 는 규율이 칸 단위로 내려온 것이며,
**대응표를 처음 채우자마자 이 구분이 필요해졌다** — `verify_grasp` · `grip_force` · `grasp_attempts` ·
`mode` 넷은 이 조사가 한 번도 본 적이 없었고, 산문 `evidence` 만 있던 시절에는 그 빈칸이 보이지 않았다.

## 4. 제약의 일곱 가지 — `limitations`

Open-RMF 가 통합 등급에 `Full Control` · `Traffic Light` 라는 **이름**을 준 것과 같은 자리다.
다만 **우리는 기종이 아니라 칸마다 붙인다** — 한 기종 안에서 스킬마다 다르다는 것이 Spot 에서 드러났기 때문이다.

| 유형 | 뜻 | 어디서 드러났나 |
|---|---|---|
| `TARGET_NOT_ADDRESSABLE` | 대상을 지목할 자리가 없다 | Orbit `navigate_to` — 갈 수 있는 곳이 미리 저작된 미션뿐 |
| `POSITION_NOT_IDENTITY` | 신원이 아니라 위치로 지시한다 | Spot `pick_place` — 이름→점 변환이 질의 시점에 굳는다 |
| `NO_TERMINAL_SIGNAL` | 끝났다고 안 알려 준다 | G1 `move_relative` — 어댑터가 시계로 적는다 |
| `NO_CANCEL_OR_PAUSE` | 도는 것을 멈출 수단이 없다 | G1 로코 · Orbit 미션 |
| `NO_PROGRESS` | 얼마나 갔는지 셀 근거가 없다 | G1 · Orbit |
| `NO_RESULT_CHANNEL` | 결과를 실어 보낼 자리가 없다 | Digit `inspect` 의 `missing`. **지금 이 유형이 붙은 칸은 없다** — 그 스킬이 `NO` 라 제약을 적을 자리가 아니기 때문이고, 유형만 먼저 세워 둔 것이다 |
| `MULTI_STEP_COMPOSITION` | 한 의미 액션이 아니라 순서의 합성이다 | Digit `pick_place` · Spot 놓기 |

★**`YES` 인 칸에도 붙는다.** G1 `move_relative` 는 닿는데 `NO_TERMINAL_SIGNAL` 이다 —
*닿긴 닿는데 어댑터가 무엇을 떠안는지* 가 판정 옆에 바로 보이는 것이 이 분류의 값이다.

## 5. 기계가 1 차로 훑을 때 — 초안의 규칙

이 단계의 괴로운 절반은 **전수 훑기**이고 그것은 기계가 싸게 한다. 다만 들이는 방법이 정해져 있다.

**초안은 `evidence_grade: "MACHINE_DRAFT"` 로 낸다.** 그리고 그 등급인 칸은 `reachable` 이 반드시
`UNKNOWN` 이다 — 스키마와 시험이 **둘 다** 막는다.

| 초안이 채우는 것 | 초안이 채우면 안 되는 것 |
|---|---|
| `survey_scope` — 무엇을 몇 개나 훑었는지 | `reachable` — 판정 |
| `parameter_map` 의 **후보와 인용** | `missing` — 부재 판정 |
| `vendor_primitive` 후보 | `adapter_must_own` — 코드 견적 |
| | `layer.vendor_layer` — 계층 |

★**왜 판정을 못 채우게 하는가.** 백지에서 시작하면 사람은 *"이게 되나"* 를 묻고, 초안을 받으면
*"이게 맞나"* 를 묻는다. **뒤엣것이 훨씬 잘 통과한다.** 초안이 주장이 아니라 **질문 모음**이어야 하는
이유이고, 그것을 사람의 성실함이 아니라 기계가 지키게 한 것이 `MACHINE_DRAFT` 다.

**환각은 매니페스트가 잡는다.** 초안이 `bosdyn.api.GraspService` 같은 없는 심볼을 짚으면
*"짚은 벤더 심볼이 그 기종 매니페스트에 있다"* 가 커밋 전에 빨개진다. 그래서 순서 2 번(매니페스트 먼저)이
기계 초안을 들이는 전제 조건이다.

**사람이 하는 일은 표를 한 줄씩 반박하는 것이다.** 산문은 통째로 받아들이거나 통째로 거부하게 되지만
표는 칸마다 걸린다.

## 6. 기계가 지키는 것과 못 지키는 것

**지킨다** — `VocabularyDistanceTest`

| 시험 | 막는 것 |
|---|---|
| 계약의 모든 스킬을 실물마다 잰다 | 스킬을 더해 놓고 안 재는 것 |
| 닿는다고 적은 것과 선언한 것이 같다 | 판정과 프로파일이 각자 옳은 채로 갈리는 것 |
| 프로파일이 선언한 스킬을 그 기종 어댑터가 든다 | 선언은 했는데 어댑터가 안 드는 것 — **미믹에서는 초록이고 실물에서 `UNSUPPORTED_SKILL` 이다** |
| 닿는 스킬은 계약 파라미터를 빠짐없이 짚는다 | 대응표에 빈칸이 남는 것 |
| YES 는 필수 파라미터를 안 본 채로 못 선다 | 안 보고 닿는다고 적는 것 |
| 짚은 벤더 심볼이 그 기종 매니페스트에 있다 | 환각 · 오타 · 벤더의 개명 |
| 기계 초안은 판정을 비운다 | AI 초안이 사슬의 뿌리로 승격되는 것 |
| 부재를 단정하려면 1 차 근거가 있어야 한다 | 짐작 위에 판정을 얹는 것 |

**못 지킨다.** 어느 것도 **잘못된 판정 자체**는 못 잡는다. 잡는 것은 빈칸 · 모순 · 범위 누락이고,
*"닿는다고 썼는데 실은 안 닿는다"* 는 실물에 붙는 날 드러난다(C-3).

그래도 이 절차의 값은 남는다 — **레시피가 맛을 보장하지는 않지만, 순서가 있으면 빠뜨릴 자리가 줄어든다.**

## 7. 남의 것과 비교하면

| | 등급을 매기는 단위 | 판단의 근거가 남는가 |
|---|---|---|
| **Open-RMF** | 기종(플릿) 하나에 하나 — `Full Control` · `Traffic Light` | 안 남는다. 등급 선택이 코드와 설정에 녹는다 |
| **openTCS** | 주문마다 `canProcess` 가 **이유를 단 참/거짓**을 낸다 | 안 남는다. 구현 안에 있다 |
| **VDA 5050** | AGV 가 `factsheet.agvActions[]` 로 선언한다(`actionType` · `actionParameters` · `actionScopes`) | 안 남는다. 선언만 남는다 |
| **여기** | **칸마다**(기종 × 스킬) | `evidence` · `survey_scope` · `missing` · `adapter_must_own` 으로 남는다 |

셋 다 이 단계를 피하지 못했다. VDA 5050 처럼 표준을 세워도 *"AGV 의 능력이 액션 설명에 대응하면
그것을 쓴다"* 는 문장이 남고, **판단은 사라지지 않고 벤더 쪽으로 옮겨갈 뿐이다.**

가져올 만한 것이 아직 둘 남아 있다 — `actionScopes`(그 스킬이 **어디서** 실행될 수 있는가)라는 축과,
새 기종을 시작할 **골격 템플릿**(`fleet_adapter_template` 의 `# IMPLEMENT YOUR CODE HERE #` 자리).
둘 다 `docs/limits.md` 에 열림으로 있다.
