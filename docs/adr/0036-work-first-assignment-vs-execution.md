# ADR 36 — 작업 배정 어휘와 실행 계약 어휘의 계층 분리 (Work-First Architecture)

- **설계 문서 참조**: §15.74, §15.76, §15.93
- **결정 일자**: 2026-09-08
- **상태**: 결정됨 (코드베이스 반영 완료)

---

## 1. 맥락 및 배경

초기 인터페이스 계약의 표준 스킬 카탈로그(`skill_catalog.proto`)는 실제 기종 연동 시 4개 중 1개만 정상 매핑되는 심각한 불일치를 겪었습니다. 원인 분석 결과, 단일 스키마가 **작업 배정(Assignment)**과 **기계 실행(Execution)**이라는 완전히 상이한 두 책임을 겸업하고 있었습니다:
- **배정 관점 (상위 비즈니스)**: "이 자재 운반 작업을 특정 로봇에게 할당할 수 있는가?" (추상적 작업 정의)
- **실행 관점 (하위 제어기)**: "로봇 액추에이터에 어떤 초당 속도 벡터와 지속시간을 하달해야 하는가?" (원자적 제어 명령)

결과적으로 MES/WMS 같은 상위 시스템이 `move_relative(forward_speed, lateral_speed, duration)` 같은 초당 미터 단위의 저수준 물리 제어 파라미터를 직접 지정해야 하는 구조적 왜곡이 발생했습니다.

---

## 2. 핵심 결정 사항

**"아키텍처의 출발점을 기체 하드웨어가 아닌 상위 비즈니스 일감(Work)으로 정의하고, 4대 계층으로 분리한다."**

| 계층 번호 및 명칭 | 소유 주체 | 상류 시스템(MES/WMS) 노출 여부 |
|---|---|---|
| **① 일감 유형 (Work Types)** | 현장 사이트 (Site) | **완전 노출** (상류와의 주요 접점) |
| **② 능력 및 자격 어휘 (Capability)** | 계약 계층 (도메인 단위) | **완전 노출** (배정 평가 기준) |
| **③ 배정 및 완료 결정 (Arbitration)** | 미들웨어 코어 (`picasso`) | 실행 결과 및 상태 통보만 노출 |
| **④ 실행 및 벤더 명령 합성 (Execution)** | 하드웨어 어댑터 (`adapter-*`) | **비노출** (어댑터 내부에 은닉) |

---

## 3. 세부 아키텍처 규칙

1. **배정 적합성 평가 공식 (`요구 ⊆ 제공`)**: 일감이 요구하는 **논리적 능력**과 **정량적 자격 조건**(가반하중, 통과 폭, 최대 속도, 팔 도달거리 등)이 기체의 선언 사양에 완전히 포함되는지 평가합니다.
2. **실행 계층의 비노출 원칙**: 개별 능력의 구체적 실행 메커니즘(단일 API 호출 또는 복합 시퀀스 합성)은 상류 시스템에 노출되지 않으며 어댑터 내부에 캡슐화됩니다.
3. **도메인 단위 어휘 경계 (발명 금지)**: 전 산업을 포괄하는 인위적인 만능 범용 어휘를 발명하지 않으며, 특정 도메인(예: 물류 이송, 설비 점검)에 특화된 실무 표준 어휘를 기반으로 정의합니다.
4. **발명 금지 등재 원칙**: 인터페이스 계약에 포함되는 어휘는 상위 엔터프라이즈 시스템이나 하위 로봇 벤더 중 적어도 한쪽에서 이미 공식 사용 중인 실재 어휘여야 합니다.

---

## 4. 도메인 주도 설계(DDD)와의 연계

- **현장 유비쿼터스 언어**: 일감 어휘는 현장 작업자의 실무 용어와 일치해야 함.
- **경계 컨텍스트 (Bounded Context)**: 능력 어휘를 도메인 단위로 명확히 분리.
- **부패 방지 계층 (ACL)**: 어댑터가 벤더 고유의 비표준 개념이 시스템 코어로 유입되는 것을 차단.
- **핵심 도메인**: 배정 및 완료 보증 엔진(`picasso`)을 코어로 두고, 실행 통신 배관은 지원 하위 도메인으로 격리.
