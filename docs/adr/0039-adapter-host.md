# ADR 39 — 기종 중립적인 단일 어댑터 호스트 서버(`adapter-host`) 구조 채택

- **설계 문서 참조**: §3.2, §15.77, §15.98, ADR 31, ADR 33
- **결정 일자**: 2026-09-10
- **상태**: 결정됨 (코드베이스 반영 완료)

---

## 1. 맥락 및 배경

초기 실물 어댑터 구현체(Spot, Digit, G1)는 남쪽 벤더 포트 연동과 표준 도메인 어휘(`adapter-core`)만을 갖추고 있었으며, 표준 gRPC 서비스를 외부에 노출하는 서버 런타임이 부재했습니다.

개별 기종마다 자체 gRPC 서버를 구축할 경우 동일한 계약 스펙에 대해 서로 다른 통신 예외 처리 및 세션 관리 로직이 분산되어, 에뮬레이터(`mimic`)와 실물 어댑터 간의 거동 일치성을 보장하기 어렵습니다.

---

## 2. 핵심 결정 사항

**"모든 기종별 어댑터는 북쪽 통신 계층으로서 기종을 일체 인지하지 않는 단일 공용 서버인 `adapter-host`를 공유한다."**

- **표준 인터페이스 추상화 (`RobotAdapter`)**: `adapter-core` 모듈에 `RobotAdapter` 인터페이스를 정의하고, 개별 기종 어댑터가 이를 구현합니다. 어댑터는 순수한 상태 변환기 역할만 수행하며 상위 비즈니스 판단을 배제합니다.
- **공용 계약 서버 (`adapter-host`)**: `HostedRobot` 컨텍스트를 기반으로 표준 gRPC 서비스 3종(`SkillService`, `TaskService`, `EventService`)을 제공합니다. 에뮬레이터(`mimic`)와 동일한 10대 응답 헤더, `sequence` 단조 증가, 태스크 이력 로깅을 단일 구현체로 집행합니다.
- **능력 투영 및 상태 발행 라이브러리 공유**: `capability`(투영 및 협상 판정)와 `uplink`(원격 발행 및 레지스트리 적재) 공용 모듈을 에뮬레이터와 호스트가 공통으로 채택하여 동작 동치성을 보장합니다.
- **역할 및 조립 분리**: `adapter-host`는 기종별 어댑터를 직접 참조하지 않으며, 특정 어댑터를 호스트에 바인딩하는 조립 책임은 기종을 인지하는 런처나 테스트 스위트가 담당합니다.

---

## 3. 결정 근거

상위 클라이언트는 기종을 모르며, 계약 계층 뒤의 구현체가 에뮬레이터인지 실물 어댑터인지와 무관하게 완전히 동일한 gRPC 상태 코드와 에러 응답을 수신해야 합니다. 서버 런타임을 단일화함으로써 통신 계층의 드리프트 가능성을 원천 차단하였습니다.
