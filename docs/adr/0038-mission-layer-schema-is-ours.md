# ADR 38 — 미션 계층의 스키마와 PoC 엔진은 우리 범위다

- **상태**: 제안 (2026-09-09) — [미들웨어 중앙 설계](../superpowers/specs/2026-09-09-middleware-core-design.md) 검토와 함께 확정한다
- **관련**: [ADR 36](0036-work-first-assignment-vs-execution.md) · [ADR 9](0009-no-declaration-without-consumer.md) · 설계 §1.3 · §9.6

## 맥락

본 설계 §1.3 은 *"미션 계층 — 배차·라우팅·자원 중재·다중 로봇 경합"* 을 비목표로 두었고, ADR 36 은 층 넷(사이트 일감 / 능력·자격 어휘 / 배정과 결정 / 실행)을 가르며 *"우리는 ④만 갖는다"* 고 적었다. 그 뒤로 시나리오를 돌릴 때마다 같은 문장이 반복됐다 — *"그것은 층 ③이 한다"*, 그리고 *"층 ③은 없다"*. 결과 어휘를 세우려 하자 *"소비자가 없다"* 가 됐고, 그래서 정준 모델이 요구하는 것들(근거 등급, `UNVERIFIED`, 부분 완료, 실패 분류)이 전부 보류됐다.

틀린 것은 경계의 위치가 아니라 **경계가 자른 것**이다. §1.3 이 빼려던 것은 배차·라우팅·자원 중재다. 그런데 "미션 계층"이라는 한 낱말로 묶으면서 **논리적 능력의 조합과 실행 상태 관리**까지 함께 밖으로 밀렸다. 이 둘은 배차와 다르다 — 조합을 하면서 상태를 안 갖는 것은 불가능하고, 상태를 갖는 자리가 곧 미션 계층이다. PoC 미들웨어는 그것을 안에 둔다.

## 결정

1. **논리적 능력의 조합과 실행 상태 관리는 picasso 의 범위다.** 배차·라우팅·자원 중재·다중 로봇 경합은 여전히 밖이다.
2. **스키마가 먼저다.** 실행 상태(두 축), 근거 등급, 취소 응답(중단점·잔여·정리), 정체성과 버전, 정준 실패 분류 — 이 정보의 모양은 조합을 누가 하든 같아야 한다. 나중에 미션 서비스가 따로 서더라도 스키마는 공유되므로, *"그 층을 안 지었으니 스키마도 안 정한다"* 는 순서가 틀렸다.
3. **엔진은 PoC 에서는 안에 둔다** — 새 모듈로, 게이트 7번(기종 분기 금지)의 대상에 넣어서. 분리하는 날 스키마를 들고 나가며, 그때 계약(④)이 안 바뀌는 것이 격리의 증거다.
4. **상류 인터페이스는 통합 테스트 수준까지다.** MES·WMS 는 우리 API 의 **예상 소비자**이지 흉내낼 시스템이 아니다 — 통합 시험이 그 역할을 하고, MES·WMS Mock 도 실제 상위 시스템 어댑터도 만들지 않는다. 반대로 AMR 플릿과 인계 설비는 우리가 **부르는 하류**라 더블이 있어야 한다(mimic 이 로봇을 대신하듯). 검증의 주는 시나리오 ①·②다.
5. **ADR 9 의 "소비자"는 이 층이다.** 소비 표면이 없는 선언을 두지 않는다는 규칙은 유지한다. 그러나 미션 계층은 밖에 있는 남의 것이 아니라 우리가 세우는 것이므로, 그것이 읽을 것을 "소비자 없음"으로 보류하지 않는다.
6. **ADR 36 결정 5·6 은 유지한다.** 실행 계층은 상류에 비노출이고, 계약에 넣는 것은 어느 한쪽이 이미 가진 것이다. 논리적 능력의 이름은 *프로젝트 정의*로 표시하고 쓴다 — 도메인 단위 어휘(결정 4)의 첫 인스턴스다.

## 근거

- 미들웨어의 책임 구간은 상류 인터페이스 · **중앙(식별자·상태·오류 체계, 명령과 결과의 상관관계, 중복·타임아웃·재연결의 공통 규칙)** · 하류 어댑터 · 상하류 Mock 이며, 정준 모델(태스크·상태·**실패 분류**·능력 표현)이 핵심 산출물이다. picasso 는 그중 하류와 검증만 지었다.
- 오늘의 시험 둘(`SequencingCellTest`·`InspectionPatrolTest`)이 계약 층에서 답할 수 있는 것과 없는 것을 갈랐다 — 부분 완료의 집계, 근거 미달의 완료, 접수 불명의 해소 순서, 결과 통보는 전부 "위 층"이었고 그 층이 없었다.
- 결과 어휘를 세우려다 "소비자 없음"으로 멈춘 것이 이 ADR 을 쓰게 한 직접 계기다. 소비자는 있었다 — 안 지었을 뿐이다.

## 대가

1. **§1.3 을 고친다.** 미션 계층 항목을 *"배차·라우팅·자원 중재·다중 로봇 경합"* 으로 좁히고, 조합·실행 상태 관리를 범위로 옮긴다. B-1 도 *"재기동 후 저장소 복원"* 으로 좁힌다.
2. **ADR 36 대가 3 의 서술**(*"지금 그 자리는 비어 있다"*)이 결정으로 바뀐다 — 비어 있는 것을 채운다.
3. **`scenarios.md` §1 의 AMR 규칙 1** 을 좁힌다. 벤더 AMR API·VDA 5050 을 구현하지 않는다는 뜻이지, AMR Fleet(Mock)에 위임하지 않는다는 뜻이 아니다.
4. **모듈이 하나 는다**(`middleware`, 이름은 검토). 게이트 7번 목록에 들어가며, 그 모듈 안에 `if robot == …` 가 생기면 게이트가 막는다.
5. **정준 실패 분류를 정하면 어댑터 셋이 다시 열린다.** 벤더 코드 → 분류 매핑과 원문 동반. 코어 여덟은 그 분류의 부분집합이 된다.

## 미결

- 도달 근거 등급을 계약(④)의 종착 갱신에도 실을지, 실행 층에서만 들지.
- 정준 실패 분류표의 확정(설계 §1.4 의 후보).
- 새 모듈의 이름과 `registry` 와의 관계(원장이 실행 상태를 적재하는가).
