# 아키텍처 결정 기록 (Architecture Decision Records, ADR)

시스템 설계 문서 §14에서 정의한 핵심 기술 의사결정 기록입니다. 번호는 설계 문서 §14의 행 번호와 엄격히 일치시켜 상호 참조성을 보장합니다.

본 디렉터리에 수록된 ADR은 코드베이스에 이미 반영된 확정 결정을 기록한 것이며, 미결정 사항을 사전에 문서화하여 기결정 사항으로 오인되는 것을 방지합니다.

## 2. 주요 아키텍처 결정 배경 및 맥락

- **ADR 36 (작업 배정과 실행 계약의 분리)**: 초기 스킬 카탈로그가 4개 중 1개만 실제 기체에 매핑되었던 근본 원인은 상위 배정 어휘와 하위 기계 실행 어휘를 단일 계약으로 혼용했기 때문입니다. 원자 실행 계약(제4계층)과 상위 미션 배정(제3계층)을 분리함으로써 최하위 저수준 기체부터 고수준 기체까지 일관되게 수용할 수 있게 되었습니다.
- **ADR 35 & 34 (사이트 명칭의 상주 위치)**: 현장 사이트 명칭의 좌표 바인딩 주체는 어댑터가 될 수 없으며, 기체 내부 세계 모델에 상주해야 합니다. 2개 이상의 실물 기종을 분석한 결과, 명칭 결속 기능은 로봇 자체 세계 모델의 지원 여부에 종속됨이 확인되었습니다.
- **ADR 39 & 33 (어댑터 모듈 형상 및 호스트 분리)**: 어댑터 모듈만이 기종 고유 지식을 보유할 수 있는 유일한 공간이며(ADR 33), 상위 클라이언트와의 통신 및 인터페이스 계약 노출은 기종을 인지하지 않는 단일 공용 호스트 서버(`adapter-host`, ADR 39)가 전담합니다.
- **ADR 37 (기체 등록 경로의 이원화)**: 플릿 관제 시스템을 통한 동적 발견과 고정 설치 기체의 운영자 수동 등록을 상이한 인입 HTTP 엔드포인트(적재 문 vs 운영 문)로 엄격히 분리하여 출처 스푸핑을 방지합니다.

## 3. 엔지니어링 거버넌스 공통 철학

본 결정 기록들을 관통하는 핵심 엔지니어링 원칙은 **"조용한 통과(Silent Pass)는 명시적 실패보다 치명적이다"**라는 점입니다. 검증 도구가 자원 누락이나 스키마 불일치를 조용히 묵인하면 런타임 장애로 전이되므로, 모든 거버넌스 규칙은 결함 주입 시 즉각적이고 명시적으로 실패하도록 설계되었습니다.
