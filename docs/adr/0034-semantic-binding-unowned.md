# ADR 34 — 의미론적 위치 매핑(Semantic Binding) 책임의 어댑터 외 격리 원칙

- **설계 문서 참조**: §4.3 (값 어휘 체계), §9.1
- **결정 일자**: 2026-09-08
- **상태**: 결정됨 (코드베이스 반영 완료)

---

## 1. 맥락 및 배경

인터페이스 계약의 표준 스킬 파라미터는 상위 사이트 수준의 의미론적 명칭을 사용합니다 (`navigate_to.location`, `pick_place.object_id`, `inspect.target`). 설계 문서 §4.3은 `location`이 "절대 좌표가 아니다"라고 명시하였습니다.

그러나 실물 기종들의 API를 분석한 결과, 벤더 제어기는 상위 의미론적 언어를 직접 이해하지 못하며 다음과 같은 저수준 표현을 요구합니다:
- **Spot**: GraphNav 내부 생성 웨이포인트 ID 문자열, 카메라 픽셀 좌표, 또는 3D 좌표 프레임
- **Digit**: 세계 모델 내부 `ObjectSelector` 쿼리 구조체
- **G1**: 속도 벡터(`SetVelocity`) 또는 하드코딩된 제스처 ID

즉, 상위 사이트 명칭을 로봇 내부의 국소 식별자/좌표로 변환하는 '의미론적 결속(Semantic Binding)' 계층이 필수적이나, 이 매핑 테이블의 소유 주체가 아키텍처 상에 공백으로 남아 있었습니다.

---

## 2. 핵심 결정 사항

**"하드웨어 어댑터는 사이트 명칭과 로봇 좌표 간의 매핑 테이블을 소유하지 않는다."**

어댑터는 상위 시스템이나 로봇 기체가 이미 제공하는 명칭 결속을 단순히 통과(Pass-through)시키거나 벤더 API 규격에 맞춰 직렬화할 뿐이며, 자체적으로 정적 좌표 변환 사전을 유지하지 않습니다.

---

## 3. 결정 근거

1. **운영 롤백 독립성 보장 (§9.1)**: 사이트 명칭 매핑 테이블을 어댑터 내부에 보관하면, 어댑터 버전을 롤백할 때 공장 시설 명칭 구성까지 과거로 되돌아가는 치명적 결합이 발생합니다.
2. **기종 간 매핑 데이터 중복 방지**: 공장 내 "도크 3번"의 물리적 정의는 로봇 기종과 무관한 전역 사실입니다. 이를 개별 어댑터마다 분산 보관하면 기종 수만큼 데이터 사본과 불일치가 발생합니다.
3. **진실 공급원(Single Source of Truth) 충돌 차단**: 기체 자체 세계 모델(GraphNav 등)이 이미 결속을 관리하는 상황에서 어댑터가 별도 사전을 유지하면 두 저장소 간의 데이터 불일치가 발생합니다.

---

## 4. 실물 기종 분석을 통한 설계 확증

- **Spot**: GraphNav 웨이포인트 주석(Annotations)에서 사람이 붙인 사이트 이름을 직접 조회하므로, 어댑터가 사전을 가질 필요가 없습니다.
- **Digit**: `ObjectSelector`를 통해 객체 이름(`name`), 태그 ID, 속성을 직접 질의할 수 있는 지능형 세계 모델을 제공하므로, 어댑터는 질의 조건을 전달하기만 합니다.
- **G1**: 내부 세계 모델이 부재하여 사이트 명칭 기반 이동을 지원할 수 없으며, 따라서 해당 스킬을 지원 목록에서 배제합니다.

결론적으로 의미론적 결속은 로봇 자체 세계 모델(ADR 35) 또는 상위 사이트 레지스트리가 관장해야 하며, 어댑터의 책임 범위에서 엄격히 배제됩니다.
