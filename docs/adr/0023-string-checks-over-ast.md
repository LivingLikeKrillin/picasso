# ADR 23 — 게이트의 구조 검사를 문자열 검사로 둔다

설계 §14의 23번. 원래는 7번 검사(기종 분기 금지)에 대한 결정이었으나, 1단계에서 **5번 검사(`contracts` 의존 0)가 같은 이유로 같은 형태가 되었다.** 이 기록은 둘을 함께 다룬다.

## 맥락

두 검사가 소스의 구조를 판정해야 한다.

- **5번** — `contracts`가 프로젝트 내 의존을 갖는가(§3.2)
- **7번** — 지금은 `client`·`mimic`·`harness`·`adapter-core`·`picasso`·`capability`·`adapter-host`·`uplink` 여덟 모듈(원래 셋에서 늘었다, `Check07ModelBranching.kt`의 `MODULES`) 소스에 기종 식별자가 등장하는가(§11.2, 2단계)

정확한 답은 각각 Gradle 빌드 그래프와 Kotlin AST에 있다.

## 결정

**둘 다 문자열 검사로 둔다.**

7번의 이유는 §11.2에 있다 — AST 분석은 우회 방법이 많고 유지 비용이 크다. **우회를 막는 것이 아니라 실수를 막는 장치다.**

5번은 다른 이유가 하나 더 있다. **게이트가 Gradle을 부르면 `gate → Gradle → gate`가 되고** 시험이 몇 초에서 몇 분이 된다. 게이트는 PR마다 도는 것이고, 느려지면 사람이 끄게 된다.

## 대가를 정확히 적는다

잡지 못하는 것을 잡는 척하지 않는 것이 이 결정의 조건이다.

**5번이 못 잡는 것:** 관례 플러그인이나 별도 `.gradle.kts`가 주입하는 프로젝트 의존.

**5번의 거짓 실패 둘:**

- 블록 주석(`/* … */`) 안의 `project(` — 줄 주석만 걷어낸다
- 루트가 **자기 자신을 위해** 갖는 프로젝트 의존 — `subprojects` 블록이 파일에 있으면 파일 전체를 훑기 때문이다. 블록의 경계를 파싱하지 않는다

**잡는 형태 셋:** `project(":x")`, `project(path = ":x")`, `projects.x`.

셋째가 중요하다. **타입세이프 프로젝트 접근자는 `settings.gradle.kts`에 `enableFeaturePreview("TYPESAFE_PROJECT_ACCESSORS")` 한 줄이면 켜지는, 코틀린 DSL 저장소에서 아주 흔한 형태다.** 처음 두 개만 잡던 정규식은 그것으로 그대로 우회됐다. 넷째 형태가 생기면 이 검사를 고쳐야 한다.

## 문자열 검사가 무력해지지 않게 하는 것

이 결정의 위험은 검사가 **조용히** 아무것도 안 잡는 상태가 되는 것이다. 셋으로 막는다.

1. **대상 파일이 없으면 실패한다.** `contracts/build.gradle.kts`를 못 찾으면 통과가 아니라 실패다 — 검사할 대상이 사라졌는데 통과하면 검사가 조용히 무력해진 것이다.
2. **실제 저장소에 대해 돌리는 시험이 있다.** 임시 디렉터리만 시험하면 이 검사가 우리 저장소를 실패시키는지조차 모른다. 루트에 `subprojects { }` 블록이 있고 `contracts/build.gradle.kts`에 `project(...)`를 언급하는 주석이 있어 거짓 실패가 나기 딱 좋은 조건인데, 통과한다.
3. **음성 케이스가 있다**(§11.2의 9번). `05-contracts-dependency`가 실제로 의존을 넣어 검사 5번이 그것을 **기대한 이유로** 막는지 본다.
