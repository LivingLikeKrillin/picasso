# ADR 23 — 정적 아키텍처 규칙 검사의 문자열 기반 구현

- **설계 문서 참조**: §14 행 23, §11.2
- **결정 일자**: 2026-09-06
- **상태**: 결정됨 (코드베이스 반영 완료)

---

## 1. 맥락 및 배경

게이트 검증 파이프라인 중 다음 2대 검사는 소스 코드의 아키텍처적 구조를 정적 분석해야 합니다:
- **검사 5번**: `contracts` 모듈의 프로젝트 내부 타 모듈 의존성 0 검증 (§3.2)
- **검사 7번**: 8개 기종 중립 모듈 소스 내 특정 벤더/모델 문자열 유입 차단 (§11.2)

가장 엄밀한 분석 방법은 Gradle 내부 빌드 모델 파싱과 Kotlin 컴파일러 AST(Abstract Syntax Tree) 분석기를 도입하는 것입니다.

---

## 2. 핵심 결정 사항

**"컴파일러 AST 파서 대신 문자열 정규식 기반의 경량 패턴 매칭으로 구현한다."**

- **유지보수 및 복잡도 절감**: AST 분석기는 컴파일러 버전 변경에 민감하고 우회 패턴이 다양하여 유지보수 비용이 과도합니다. 본 정적 검증의 목적은 악의적인 코드 난독화 방어가 아닌 **개발자의 부주의한 결합 실수 방지**입니다.
- **빌드 성능 보장**: 게이트가 Gradle 데몬 내부 모델을 직접 호출하면 재귀적 프로세스 구동(`gate → Gradle → gate`)으로 인해 검사 시간이 수 초에서 수 분으로 급증하여 PR 검증 사이클을 저해합니다.

---

## 3. 검증 대상 패턴 및 알려진 한계

### 검사 5번(의존성) 탐지 대상
- `project(":x")`
- `project(path = ":x")`
- `projects.x` (Kotlin DSL 타입세이프 프로젝트 접근자 지원)

### 정규식 검사의 구조적 사각지대 및 한계
- 외부 플러그인이나 별도 스크립트 파일이 간접 주입하는 의존성은 탐지하지 못합니다 (§15.11).
- 블록 주석(`/* ... */`) 내부의 구문이나 멀티모듈 루트의 자기 자신 참조에 대해 오탐(False Positive)을 피하기 위해 줄 주석 기반으로 필터링합니다.

---

## 4. 정규식 무력화 방지 안전장치

1. **대상 파일 부재 시 즉시 실패**: 검사 대상 파일(`contracts/build.gradle.kts` 등)이 존재하지 않으면 성공으로 스킵하지 않고 즉시 빌드 실패를 유발합니다.
2. **실제 저장소 대상 회귀 테스트**: 테스트 전용 모의 디렉터리뿐만 아니라 실제 저장소 소스를 대상으로 검증을 구동하여 오탐이 발생하지 않음을 상시 검증합니다.
3. **음성 하네스(Negative Harness) 연동**: `05-contracts-dependency` 케이스를 통해 의존성이 주입되었을 때 정확히 기대한 사유로 빌드가 차단되는지 기계적으로 검증합니다.
