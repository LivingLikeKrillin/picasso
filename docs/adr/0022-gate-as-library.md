# ADR 22 — `gate`를 라이브러리로 두고 호출 지점을 둘로

설계 §14의 22번. §11.1이 결정 자체를 담고, 이 기록은 **1단계 구현이 그 결정에 붙인 값**을 담는다.

## 맥락

같은 규칙을 두 곳이 집행해야 한다. CI는 PR을 막고, `registry`는 개정판 등록을 막는다. 둘이 다른 답을 내면 "CI는 통과했는데 등록이 거부됐다"가 일어나고, 그 순간 사람은 둘 중 하나를 믿지 않게 된다.

## 결정

**구현은 하나이고 호출 지점이 둘이다. 기준선은 인자로 받는다.**

| 호출 지점 | 프로파일 기준선 | 계약 기준선 |
|---|---|---|
| CI | 베이스 커밋의 프로파일 문서들 | `../.git#ref=<베이스 SHA>,subdir=contracts` |
| `registry` 등록 | 같은 `profile_id`의 직전 `ACTIVE` 개정판의 `document` | (없음 — buf를 부르지 않는다) |

**게이트는 git을 해석하지 않는다.** 계약 기준선은 호출 지점이 만든 문자열을 `buf breaking --against`에 그대로 넘긴다. 게이트가 git을 알면 `registry`가 같은 코드를 쓸 수 없다.

**6번은 언제나 프로파일 `document`를 diff한다** — 평탄화 테이블이 아니다. CI에는 DB가 없으므로 입력을 문서로 통일해야 두 호출이 같은 답을 낸다.

## 구현이 이 결정에 붙인 것

설계에는 없었지만 구현하면서 필요해진 것 셋이다. **셋 다 "조용히 통과하는 것을 막는다"는 한 가지 이유에서 나왔다.**

### 자원 선언과 건너뜀

검사는 요구 자원(`Resource`)을 선언하고, 없으면 건너뛰되 **그 사실을 출력에 남긴다**(§3.1). 그런데 그것만으로는 부족했다.

**게이트가 아무 검사도 돌리지 않아도 종료코드가 0이었다.** 글롭 오타나 빈 디렉터리로 프로파일이 0장이면 검사 3·4·6이 전부 건너뛰고 초록불이 난다. 로그에 `SKIP`이 찍히지만 **초록 빌드의 로그는 아무도 읽지 않는다.**

그래서 호출 지점이 `required` 자원을 선언한다. 없으면 건너뜀이 아니라 **실패**다. §11.1이 상시 건너뜀으로 인정하는 것은 검사 6번의 `REGISTRY` 하나뿐이므로, 나머지가 없는 것은 배선이 깨진 것이다.

### `null`과 빈 것의 구분

기준선에서 이 구분이 세 번 값을 했다.

| 값 | 뜻 | 처리 |
|---|---|---|
| `null` | 기준선 출처에 닿지 못했다 | 검사가 건너뛴다 |
| 빈 맵 | 신규다 | 파괴 검사가 통과로 처리한다(§11.1) |

**깨진 기준선 문서 하나가 이 구분을 무너뜨렸다.** 파싱 실패한 문서를 조용히 빼면 빈 맵이 되고, 디렉터리는 존재하므로 자원은 "있다"로 잡힌다. 그러면 검사 6번이 모든 프로파일을 신규로 분류해 **경고 한 줄 없이 완전한 `PASS`**를 낸다. 입력 수집기가 시끄럽게 죽는 것으로 막았다.

같은 형태가 CI에도 있었다. `git ls-tree`가 빈 목록을 내면 빈 기준선 디렉터리가 만들어지는데, 그것을 넘기면 같은 결말이 된다. CI가 "빈 기준선"과 "기준선 못 얻음"을 구분해 준다.

### 기준선을 기종 좌표로 키잉

기준선을 **파일 경로**로 키잉하면, 프로파일 파일 이름을 바꾸면서 스킬을 지우는 PR이 "기준선이 없으니 신규"로 분류되어 파괴 검사를 통째로 지나간다. 리네임은 악의 없이도 밟는다.

§8.3이 문서의 동일성을 `(vendor, model)`로 규정하고, `registry` 호출 지점에는 파일 경로라는 것이 아예 없다. **경로 키잉으로는 "두 호출이 같은 답을 낸다"가 성립할 수 없다.**

## 대가

~~**`registry`가 아직 없어 두 번째 호출 지점이 검증되지 않았다. 3a에서 붙는다.**~~ → **검증됐다.** `registry/build.gradle.kts`가 `implementation(project(":gate"))`로 붙고, `registry/src/test/kotlin/dev/picasso/registry/GateLedgerWiringTest.kt`가 그것을 실제 원장을 상대로 돌린다. "같은 코드가 두 곳에서 같은 답을 낸다"는 주장은 이제 **실측된 것**이다.

그것을 줄이려고 `GateInput`이 두 호출 지점의 차이를 자원 유무로만 표현하게 했다 — `registry`는 `REPO`·`BUF`·`CHANGED_FILES` 없이 문서와 디스크립터를 주고, CI는 `REGISTRY` 없이 나머지를 준다. 코드 경로가 갈라지지 않는다.
