# ADR 22 — 게이트 검증 로직의 단일 라이브러리화 및 다중 호출 지점 지원

- **설계 문서 참조**: §14 행 22, §11.1
- **결정 일자**: 2026-09-06
- **상태**: 결정됨 (코드베이스 반영 완료)

---

## 1. 맥락 및 배경

인터페이스 계약과 기종 프로파일의 정합성 검증 규칙은 개발 단계(CI 파이프라인의 PR 검증)와 운영 단계(`registry` 서비스의 런타임 개정판 등록) 양쪽에서 동일하게 집행되어야 합니다. 검증 엔진이 두 곳에 분리되어 서로 다른 로직으로 동작할 경우, "CI에서는 정상 통과된 프로파일이 실제 런타임 등록 시에는 거부되는" 치명적인 정책 드리프트가 발생할 수 있습니다.

---

## 2. 핵심 결정 사항

**"검증 구현체(`gate`)는 단일 공유 라이브러리로 개발하고, 호출 환경에 따라 비교 대상 기준선(Baseline)을 매개변수로 주입받는다."**

| 호출 컨텍스트 | 프로파일 비교 기준선 | 인터페이스 계약 비교 기준선 |
|---|---|---|
| **CI 파이프라인** | Git 베이스 커밋에 체크인된 프로파일 문서 목록 | `../.git#ref=<베이스 SHA>,subdir=contracts` |
| **`registry` 런타임** | 동일 `profile_id`를 가진 직전 `ACTIVE` 상태의 원장 문서 | 미적용 (`buf` 도구 미호출) |

### 아키텍처 경계
- **Git 비의존성 유지**: 게이트 검증 엔진 자체는 Git 명령어를 직접 파싱하지 않으며, CI 호출 스크립트가 구성한 기준선 문자열을 그대로 `buf breaking`에 전달합니다.
- **문서 단위 비교 통일**: 검사 6번(파괴적 변경 검증)은 DB 평탄화 테이블이 아닌 원본 프로파일 문서를 직접 대조하여, DB가 없는 CI 환경과 DB를 보유한 레지스트리 환경이 완전히 동일한 판정 결과를 도출하도록 보장합니다.

---

## 3. 구현 단계의 핵심 안전 메커니즘

- **자원 선언 및 무검증 통과(Silent Pass) 방지**: 검사 대상 파일이나 프로파일이 존재하지 않을 때 조용히 성공(Exit Code 0)으로 종료되는 것을 방지하기 위해, 호출 지점에서 `required` 자원을 명시적으로 선언하도록 하였습니다. 필수 자원 결손 시 즉시 빌드 실패를 유발합니다.
- **`null`과 빈 컬렉션의 엄격한 분리**: 기준선 소스에 접근 실패한 상태(`null` → 검사 스킵)와 최초 신규 등록 상태(빈 맵 → 정상 통과)를 엄격히 분리하여, 파싱 오류로 인한 기준선 누락이 신규 등록으로 오인되어 파괴적 변경 검증을 우회하는 결함을 차단했습니다.
- **기종 복합 키(`vendor, model`) 기반 인덱싱**: 기준선을 파일 경로로 키잉할 경우 파일명을 변경하며 스킬을 삭제하는 파괴적 변경을 탐지하지 못하므로, 프로파일의 논리적 고유 식별자인 `(vendor, model)`을 기준으로 변경 이력을 추적합니다.

---

## 4. 검증 결과

`registry` 모듈이 `gate` 라이브러리를 의존성으로 참조하며(`implementation(project(":gate"))`), `GateLedgerWiringTest`를 통해 실제 운영 원장 데이터를 상대로 CI와 완전히 동일한 검증 결과가 도출됨을 실증하였습니다.
