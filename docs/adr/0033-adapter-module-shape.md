# ADR 33 — 기종 고유 지식을 격리 수용하는 전용 어댑터 모듈 아키텍처

- **설계 문서 참조**: §11.2 (게이트 검사 7번), ADR 31
- **결정 일자**: 2026-09-08
- **상태**: 결정됨 (코드베이스 반영 완료)

---

## 1. 맥락 및 배경

게이트 검사 7번은 기종 중립 모듈(`client`, `mimic`, `harness`, `picasso` 등) 내에 특정 벤더나 모델 명칭이 유입되는 것을 엄격히 차단합니다. 이는 단일 클라이언트 코드로 이종 기체를 제어한다는 시스템의 핵심 목표를 지키기 위한 장치입니다.

그러나 하드웨어 어댑터는 정의상 대상 로봇 기체의 고유 제어기 API, FSM 상태 코드, 센서 프로토콜을 반드시 인지해야 합니다. 따라서 어댑터 코드를 기종 중립 모듈 내에 혼재시키지 않고 기종 고유 지식을 안전하게 격리할 전용 모듈 구조가 필요했습니다.

---

## 2. 핵심 결정 사항

**"기종마다 독립된 전용 모듈을 신설하고 `adapter-<vendor>-<model>` 명명 규칙을 적용한다."**

- 어댑터 모듈은 게이트 검사 7번(기종 분기 금지)의 검사 대상 모듈 목록에서 제외됩니다.
- 어댑터 모듈은 표준 인터페이스 계약(`contracts`)과 공통 북쪽 어휘(`adapter-core`)만을 의존하며, 타 기종 모듈이나 상위 레지스트리 내부를 참조하지 않습니다.

---

## 3. 결정 근거

1. **기종 비인지 원칙의 경계 명확화**: 게이트 검사 7번의 본질은 "시스템 전체에서 아무도 기종을 몰라야 한다"가 아니라, **상위 클라이언트, 에뮬레이터, 미들웨어 코어가 기종을 몰라야 한다**는 것입니다. 기종 지식이 상주할 명확한 전용 공간(어댑터)을 제공함으로써 나머지 계층의 순수성을 보존할 수 있습니다.
2. **벤더 바이너리 및 라이선스 격리 (ADR 31)**: 기종별 SDK 라이선스의 상이한 제약 조건을 개별 모듈 단위로 격리하여 상호 오염을 방지합니다.
3. **남쪽 포트 추상화를 통한 무실기 컴파일 지원**: 벤더 SDK를 직접 호출하지 않고 남쪽 포트 인터페이스(`G1Link`, `SpotLink` 등)를 경유하도록 설계하여, 전용 바이너리나 하드웨어 연결 없이도 단위 테스트 및 빌드가 가능하도록 보장합니다.

---

## 4. 트레이드오프

- 어댑터 내부에 기종을 초월한 일반 공통 로직이 혼재될 경우를 대비하여 공용 모듈인 `adapter-core`를 추출하였으며, `adapter-core`는 다시 게이트 검사 7번의 엄격한 기종 비인지 감시 대상에 포함되었습니다.
