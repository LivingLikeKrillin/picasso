# 시스템 한계 및 미결 과제 대장 (Known Limits & Technical Debt)

본 문서는 `picasso` 미들웨어 아키텍처 및 구현 상에 존재하는 **알려진 한계(Known Limitations), 스코프 외 제외 항목, 기술 부채 및 해소 조건**을 체계적으로 추적 관리하기 위한 엔지니어링 대장입니다.

설계 문서의 §15는 전체 변경 이력과 배경을 누적 기록하는 일지이며 (번호가 158 까지 갔고), 본 문서는 현재 시점에서 유효한 미결 항목만을 분류하여 제공합니다. 해결 완료된 항목은 일지에 `(닫힘)` 처리되고 본 대장에서는 정리됩니다.

---

## 분류 체계 (3대 범주)

| 분류 | 정의 및 성격 | 해소 전략 |
|---|---|---|
| **의도적 제외 (Out-of-Scope)** | 아키텍처 설계 상 시스템의 책임 범위 외로 확정한 비목표 항목 | 설계 원칙을 변경하지 않는 한 해소 대상이 아님 |
| **내부 미결 (Internal Open)** | 저장소 내부의 코드 구현 및 자동화 검증을 통해 자체 해소 가능한 기술 부채 | 구체적 구현 사양 충족 시 종결 |
| **외부 미결 (External Open)** | 실물 하드웨어, 공장 인프라, 상위 엔터프라이즈 시스템 연계 등 외부 조건이 필수적인 항목 | 현장 실증 및 상위 연계 프로젝트 진행 시 종결 |

| §15.9 | 다중 사이트 격리 배포 정책 | 단일 사이트 내 이기종 연계에 집중하며 멀티 사이트 브리징은 비목표 |
| §15.33 | mimic 제어 채널의 인증 미적용 | 테스트 도구로서 루프백(Loopback) 바인딩으로 보안 격리 유지 |
| §15.37 | 거절 테이블의 `robot_id` 외래키 미적용 | 미등록 기체로부터 유입된 비정상 거절 요청도 운영자가 진단할 수 있도록 보존 |
| §15.124 | 사적 맥락 검사 시 사업장/조직 명칭 배제 | 특정 조직 명칭을 코드에 하드코딩하는 유출을 방지하기 위해 저장소 외부에 보관 |
| §15.87 | 점검 결과 수용 필드의 단순성 | 점검 데이터 스키마는 상위 보전 시스템이 결정하므로 계약 인터페이스를 임의로 고정하지 않음 |
