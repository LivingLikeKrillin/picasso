# `uplink` — 발신자의 위쪽 결선

브로커 발행(§4.7 의 세 스트림)과 레지스트리 적재(§9). **미믹과 어댑터 호스트가 나눠 쓴다.**

## 왜 따로 있나

둘 다 *기체가 자기 상태를 바깥에 알린다* 는 같은 일을 한다. 두 벌로 두면 규칙이 갈리고, **실제로 갈렸다** —
드레인 뒤 이중 발행이라는 같은 결함을 미믹과 호스트가 각각 한 번씩 밟았다(§15.99). 그래서 합쳤다.

## 무엇이 여기 있나

| 묶음 | 무엇 |
|---|---|
| `Publisher` · `Topics` · `MqttPublisher` | 발행 — 토픽 형식(§5.5), retain, Last Will. `Publication` 이 **`sequence` 가 이미 붙은 상태**인 것이 요점이다: 번호를 붙이기 전에 장애가 끼면 소비자가 결손을 아예 못 본다 |
| `report/RegistryLink` · `IngestBridge` | 적재 — 발행을 감싸 원장으로 보낸다. **발신자는 그것을 모른다** |
| `report/Http*` · `Fallback*` | 적재의 전송과 **파일 폴백**. 삼킨 것을 버리면 그 사이의 전이가 통째로 사라진다 |
| `report/RobotDiscovery` | ADR 37 의 적재 문 — 발견한 기체를 올린다 |

## 정직하게 적어 둘 것

- **기본값은 아무 데도 안 보낸다**(`Publisher.NONE`). 붙이는 것은 조립하는 쪽의 일이다.
- **적재 토큰은 기체마다 배포된다.** 그래서 운영자 문과 합치면 안 된다(§15.38).
