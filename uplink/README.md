# uplink — 비동기 상태 발행 및 레지스트리 적재 클라이언트 (Uplink Telemetry & Ingest)

로봇 런타임에서 외부 메시지 브로커로 비동기 상태를 발행(MQTT 3대 스트림, §4.7)하고, 운영 레지스트리에 기체 생존 및 태스크 진행 상태를 인입 적재(HTTP Ingest, §9)하기 위한 공용 통신 라이브러리입니다. 에뮬레이터(`mimic`)와 실물 어댑터 호스트(`adapter-host`)가 공통으로 채택하여 사용합니다.

---

## 1. 모듈 통합 배경: 발신 파이프라인 일원화

에뮬레이터와 실물 어댑터 호스트 모두 로봇의 내부 상태 전이를 외부 시스템에 전달하는 동일한 역할을 수행합니다. 상태 전달 파이프라인이 분리되어 있을 경우 이벤트 직렬화 및 시퀀싱 로직의 불일치가 발생할 위험이 있습니다 (과거 큐 드레인 후 이중 발행 결함이 양쪽 모듈에서 각각 발생했던 이력 해소, §15.99).

---

## 2. 주요 구성 패키지

| 패키지 및 클래스 | 아키텍처 역할 및 통신 사양 |
|---|---|
| `Publisher` · `Topics` · `MqttPublisher` | 브로커 상태 발행 — 토픽 명명 규약(§5.5), QoS, Retain 플래그, Last Will 메시지 구성. 모든 `Publication`은 전송 전에 엄격한 단조 증가 `sequence` 번호를 선제 바인딩하여 네트워크 단절 시에도 수신자가 결손을 감지하도록 보장 |
| `report/RegistryLink` · `IngestBridge` | 레지스트리 적재 브리지 — 브로커 발행 이벤트를 래핑하여 원장 적재 HTTP 엔드포인트로 전송 (발신 비즈니스 로직에는 투명하게 동작) |
| `report/Http*` · `Fallback*` | HTTP 전송 계층 및 네트워크 단절 시 **로컬 디스크 파일 폴백(File Fallback)** 메커니즘 지원 (임시 유실된 이벤트의 전이 이력 보존) |
| `report/RobotDiscovery` | 동적 기체 자동 발견(ADR 37) 적재 클라이언트 — 런타임에 탐지된 신규 기체 정보를 레지스트리에 자동 등록 |

---

## 3. 엔지니어링 주의 사항 및 알려진 한계

- **기본 발행 비활성화**: 조립 측에서 명시적으로 브로커를 주입하지 않을 경우 기본값은 무동작(`Publisher.NONE`)으로 초기화됩니다.
- **적재 토큰 격리 원칙 (§15.38)**: 기체 단위로 배포되는 적재 토큰은 상태 전송 전용이며, 시스템 구성을 변경하는 운영자 권한 엔드포인트와 물리적으로 격리되어야 합니다.
