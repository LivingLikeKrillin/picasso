# adapter-host — 공용 어댑터 호스팅 런타임 서버 (Adapter Host Server)

기종별 구현체(`RobotAdapter`)를 주입받아 표준 인터페이스 계약(제4계층)의 gRPC 서비스를 노출하는 **기종 중립 계약 서버**(ADR 39)입니다. 4개 기종별 어댑터가 개별 서버를 구축하지 않고 본 공용 호스트를 공유합니다.

어댑터 계층 전체 아키텍처는 `adapter-core`(북쪽 표준 어휘) · `adapter-host`(공용 계약 서버) · `adapter-<기종>`(벤더 연동 전담, ADR 33)의 3계층으로 분리되어 있습니다.

---

## 1. 아키텍처 설계 원칙: 단일 서버 인프라를 통한 거동 일관성

상류 클라이언트(`client`, `picasso`)는 기종을 일체 인지하지 않으므로, 인터페이스 계약 뒤의 구현체(에뮬레이터 및 실물 어댑터) 간 거동 차이가 없어야 합니다. 서버 런타임을 단일화함으로써 통신 처리 로직의 불일치 위험을 최소화합니다.

또한 `capability`(능력 투영 및 협상 판정)와 `uplink`(원격 상태 발행 및 적재) 공용 라이브러리를 공유하여, `harness/HostParityTest`를 통해 에뮬레이터와 실물 어댑터 간의 완전한 동작 동치성을 유지합니다.

---

## 2. 어댑터 계층 3단계 분리 구조

| 계층 | 인지 영역 (Responsibility) | 격리된 영역 (Encapsulation) |
|---|---|---|
| `adapter-core` | 계약 도메인 어휘 (`Acceptance`, `Applied`, `HoldObservation`, `ProgressObservation`, `SiteNames`) | 기종 고유 사양, 네트워크 전송 계층 |
| `adapter-host` | 인터페이스 계약 gRPC 엔드포인트, 태스크 이력 관리, 3대 비동기 스트림 발행, 능력 협상 | 기종 고유 사양, 벤더 API 프로토콜 |
| `adapter-<기종>` | **벤더 고유 연동 전담** — 남쪽 통신 포트, 벤더 심볼 인용(`@VendorSurface`), 기체 조립 | 상위 계약 소비자의 정체 |

---

## 3. 결정론적 펌프(Pump) 구동 및 비동기 스레드 배제

모든 인입 RPC는 내부 상태 갱신 틱인 `pump`를 선행 통과합니다. 호스트는 어댑터에 기체 상태를 질의하고 변경된 전이만을 기록하여, `WatchTask` 스트림이 타 RPC에 의한 중간 전이를 놓치는 레이스 컨디션을 방지합니다.

---

## 4. 알려진 한계 및 엔지니어링 고려 사항

- **실물 기체 연동 미수행 (C-3)**: 어댑터 4종 중 어느 것도 실물 하드웨어에 연동 검증되지 않았으며, 네트워크 와이어를 통과하는 Orbit 역시 테스트용 스텁 서버와 연동된 상태입니다 (상세 등급: [`docs/verification.md`](../docs/verification.md) 5·6번).
- **단일 프로세스 다중 기체 호스팅 (ADR 21)**: 현재 구현은 PoC 개발 편의를 위해 단일 호스트 프로세스에서 복수 기체를 수용하도록 구성되어 있습니다.
- **재개/재시도 미지원 (§15.113)**: 포트 인터페이스 사양은 확장되었으나 기종별 어댑터의 기본값은 아직 미지원 상태입니다.
