// tools/adapter-template — 컴파일되지 않는다.
package dev.picasso.adapter.<vendor>

import dev.picasso.adapter.core.VendorSurface

/**
 * 남쪽 경계 — <기종> 이 **실제로 말하는 것**.
 *
 * ## 벤더의 분할을 그대로 옮긴다
 *
 * 여기 적는 층은 우리가 고른 것이 아니라 **벤더가 이미 가른 것**이다. 우리 계약의 태스크
 * 생명주기와 모양이 같은 층이 어느 것인지가 `profile/distance/<기종>.json` 의
 * `layer.vendor_layer` 이고, 스킬마다 어느 층에 타는지가 `execution_scope` 다.
 *
 * ## 널로 둔다 — 그리고 그것이 스킬마다 다르다
 *
 * 표면이 없을 수 있으면 `?` 로 둔다. **표면 하나가 없으면 그것을 쓰는 스킬만 죽고 나머지는
 * 돈다** — Spot 에서 명령 계층만 있으면 `move_relative` 는 돌고 `navigate_to` 는 못 돈다.
 * 기종 단위가 아니라 표면 단위로 보는 것이 이 면의 요점이다.
 *
 * ## 원문을 저장소에 안 들인다
 *
 * 벤더 SDK 는 여기 없다. 들어오는 것은 **이름과 원본의 sha256** 뿐이고(`vendor-manifest.txt`),
 * 아래 `@VendorSurface` 인용이 그 매니페스트와 대조된다 — 없는 이름을 짚으면 빨개진다.
 * 남쪽이 포트라 **SDK 없이 컴파일되고 시험이 돈다.**
 */
interface <기종>Link {

    /**
     * 시키는 표면. 우리 태스크 생명주기와 모양이 같으면 `execution_scope` 가 `MISSION` 이다.
     *
     * ★ 인용은 **벤더 원문의 이름**이어야 한다. 요약이나 제3자 래퍼를 근거로 삼지 말 것 —
     *   그렇게 해서 한 기종의 판정 넷이 통째로 뒤집힌 적이 있다.
     */
    @get:VendorSurface("<벤더.원문.심볼>")
    val <표면>: <표면>Layer?

    /**
     * 묻기만 하는 표면(있으면). 이름을 로봇의 id 로 옮기는 자리가 대개 여기다 —
     * **표를 어댑터가 갖지 않고 로봇의 표에 매번 묻는다**(ADR 34 · ADR 35).
     */
    @get:VendorSurface("<벤더.원문.심볼>")
    val <조회면>: <조회면>Layer?
}
